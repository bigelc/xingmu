# 开发约定

桌面端使用 Electron 与原生 JavaScript / HTML / CSS，没有 React 或 TypeScript 编译步骤；官网的 React / Vinext 工程独立位于 `website/`。

## 分层

主进程负责系统权限、文件、网络、加密和服务；`preload.js` 只暴露白名单桥接接口。渲染层只经桥接调用，保持 context isolation、sandbox 与 CSP，不直接访问 Node。纯领域计算放到可测试模块，保持 UI、平台能力与存储可分离。

## 状态与兼容

不要随意重命名现有 LocalStorage 键或丢弃旧工作区。持久化修改要覆盖迁移、读写失败和回滚；异步结果绑定请求代次与来源身份，不能把旧结果写到新选项。页面隐藏后停止展示性轮询，录音和计时等业务生命周期单独处理。

## 数据边界

IPC 验证可信主 frame、当前功能状态与严格参数白名单。远程请求验证协议、公开地址、每次重定向、超时和响应大小；内部配置凭据不回传渲染层。不得把远端网页或模型结果当脚本执行，不把原始新闻 HTML 注入页面。

账户金额按币种分开；账单与本程序统计分开；无数据与明确为零分开。导入仅接受系统对话框选择的文件，不接受 renderer 提供任意路径。保存统计前脱敏，勿提交真实账单、密钥、用户名目录或用户截图。

## 样式与验证

浅色主题位于 `renderer/theme-light.css`，尺寸与主题颜色尽量使用变量。保留键盘焦点、可读对比、`prefers-reduced-motion` 和窄屏滚动。首页布局必须无空洞、交叠或越界；测试要验证实际行为而非逐行复刻实现。

修改后运行相关检查，再按变更范围运行完整 `npm test`。Electron 测试使用隔离 profile 与模拟凭据，不发起真实付费调用，不与用户运行中的应用争用。安装包、线上发布、真实设备和真实 API 的验证要分别报告。
