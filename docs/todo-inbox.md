# 本地待办收件箱

本机脚本或 AI 助手将 JSON 放入当前工作区 `todo-inbox/`。应用启动时及运行中约每 2 秒检查，只追加待办，不修改或删除已有条目。当前路径可从「设置 → 数据目录」查看；换工作区后收件箱随之切换。

顶层可为 `{ "todos": [...] }` 或数组，见 [示例文件](todo-inbox-example.json)。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `text` | 是 | 最多 80 个字符 |
| `category` | 是 | `P0`–`P3`，或当前分类显示名；忽略大小写和多余空格，冲突时以固定 ID 为准 |
| `deadline` | 否 | ISO 8601 或毫秒时间戳；无时区按本机时间，仅日期取当天 23:30；省略为导入当天 23:30 |
| `id` | 否 | 字母、数字和 `. _ : -`，最长 128；已有 ID 不重复添加 |

推荐先写临时文件再改名。以 `.` 开头或不是 `.json` 后缀的文件不会导入。每个文件最多 1 MB、200 条，非法条目跳过，不影响同文件其他有效条目。

处理后文件移到 `todo-inbox/processed/`，加时间前缀，并生成同名 `.report.json`：

- `imported`：全部导入；`partial`：部分导入；`none`：没有新增；`rejected`：文件无法解析或超限。
- 报告的 `imported` 列出新增 ID；`skipped` 按从 0 开始的 `index` 说明跳过原因；`warnings` 提示过期时间等情况。

省略 ID 时按文件内容与序号生成稳定 ID，完全相同的文件再放一次不会重复，除非此前条目已删除。`processed/` 不自动清理，可手动管理。不要把包含个人待办的收件箱或处理报告提交到公开仓库。
